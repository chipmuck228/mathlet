# 原题核对：提取内容的人工核对与固定名称文件

“原题核对”只负责忠实保存人工确认后的提取正文和配图关联，不负责判定试题答案、数学结论或解题逻辑是否正确。解答、核验、分类与思路提取属于后续研究流程。

## 页面

保留原始资料选择与右侧“原始文档 · 只读”。移除原“连续核对”工具栏、范围选择、逐块初次提取记录和提取注意事项面板。左侧“核对”仍显示每个可编辑内容块及原配图。

- 点选内容块或进入编辑后，该块显示“已核对”按钮。点击会保存该块当前文字并记录人工确认，其他块的未保存编辑不会丢失。
- “保存核对文件”统一保存当前全部修改。正文实际修改但尚未点击“已核对”的块记录为待核对，不替人自动确认；其他已核对块保持原状态。
- 已核对的块可再次编辑和核对。仅重复确认相同正文不推进内容修订，不无故让已有下游研究失效；正文或核对状态实际改变仍保留正常修订与依赖失效行为。
- 不再以未转换公式、上下标提示、公式标记是否完整或 LaTeX 能否渲染作为人工核对的准入条件。原始字符串原样保存，不猜测、删除或补全。可选公式预览仍采用原安全渲染器；预览失败不阻止保存正文或人工确认。
- 网络、文件读写和实际版本冲突仍显示具体错误，不再附加过去那段通用的“本次范围未保存／请复制后重新载入”提示。失败不会清空当前编辑。

## 文件与反复打开

每份原始资料对应一份逻辑核对记录和一个 JSON 文件，保存在当前 `MATHLET_DATA_DIR`（默认项目 `data`）下的 `source-reviews/`。例如：

`2026-11-13_21-22-23-456789.json`

名称采用首次创建核对记录时的北京时间（日期、时分秒、微秒）。后续保存、重新核对、恢复已下载内容，都保留本机此记录最初的文件名和创建时间，只更新正文、状态、保存时间及内部修订号。不同原件的同一微秒命名冲突会确定性顺延微秒，避免互相覆盖。

可以：

1. 从“打开核对记录”选择已保存文件，自动打开对应原件与当前核对状态。
2. 点击“重新打开核对记录”，恢复本机已保存内容；有未保存修改时仅询问是否放弃这些修改。
3. 下载当前核对 JSON。工作台内的同名文件持续更新；浏览器下载目录是否自行追加编号由浏览器的下载规则决定。
4. 在选中对应原始资料后，通过“打开本地核对文件”恢复先前下载的 JSON 正文与核对状态。原件、原提取正文及配图不被覆盖。核对文件不打包原始 DOCX/PDF，仍需保留本机对应原件。

导入仅检查文件格式、原件身份、内容块对应关系和保存修订，不检查数学或公式正确性。JSON 中的任意路径、预览 HTML 或配图地址不会用于改写原件或加载外部资源。导入记录沿用原先保存的逐块核对时间；没有历史时间时不捏造。

## 保存与兼容

数据库中的整份核对快照是恢复依据，每次修改在同一事务中保存文本、核对状态及快照。JSON 本地文件通过临时文件原子替换，以固定名称更新；下载接口直接使用数据库最新快照。本地文件暂不可写时，会明确显示“结果已保存在数据库、本地 JSON 尚未写入”，可下载或恢复文件写入后重新打开。

迁移9新增核对记录与历史快照表，保留原始资料、提取正文、既有人工核对状态及旧交付物。已有核对状态在首次升级时建立统一记录，采用本次创建记录时间命名，不把上传时间冒充历史核对时间。原有单块及批量保存接口也同步整份核对记录，防止新旧入口产生不同版本的结果。

下游读取的仍是相同来源块 ID、人工正文和核对状态。改变来源不会改写既有不可变题目或研究文件；后续研究中的必要条件与推理仍需另行核验。原始提取信息在数据库留存，只从核对页面去掉不必要的展示。

## 验证

覆盖逐块人工确认、不因无法渲染公式拒绝确认、其余未保存编辑保留、固定文件名、保存重开与导入、原件不变、历史状态迁移、重复确认不改变内容修订、实际来源修改撤销受影响批准、冲突时整批不写入，以及本地文件写入失败后的数据库恢复。
