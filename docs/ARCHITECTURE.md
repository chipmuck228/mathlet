# Mathlet 本地架构

## 进程与目录

前端为 React + TypeScript + Vite + Tailwind。shadcn/ui 的组件源码放在 apps/web/src/components/ui，按需扩展，不引入另一个界面运行服务。开发时 Vite 将 /api 代理到 127.0.0.1:8000。

FastAPI 提供资料、编辑与审核接口，Worker 使用相同 Python 包执行耗时解析。SQLite 持久化业务状态，原件与图片保存在文件目录。MATHLET_DATA_DIR 可覆盖默认位置，API 与 Worker 必须一致。启动脚本检查端口并终止子进程组。

此版是单机单工作区；一个 Worker 使用文件锁。API 短事务允许编辑请求并发，写入使用 revision 做乐观并发控制。以后多用户协作需要身份、权限、共享文件服务和数据库迁移，不应把当前服务直接暴露到公网。

## 数据对象

| 对象 | 内容与约束 |
| --- | --- |
| Document | 原文件名、类型、资料类别、导入状态、时间；原件路径使用内部 ID |
| Block | 来源块、顺序、位置、初始安全预览、修正文本、图片、警告、核对状态、修订号 |
| Job | 资料读取任务、状态、消息、时间 |
| Draft | 标题、正文、来源 ID、有序修订号、批准对应修订、审核人 |
| Comment | 绑定草稿与修订的批注；不是自动已解决标记 |
| Release | 固定草稿、修正原题、资料名、图像数据与审核信息的快照 |

基础版正文为纯文本；结构化段落类型、数学编辑器和完整修订差异将在后续引入。每次编辑递增修订，当前不保留所有历史正文；批注保留其修订号，交付版本保存完整快照。不能把此能力描述为完整文稿版本历史。

## 导入与恢复

上传：限制扩展名与大小，保存原件，再提交 SQLite 中的 queued 任务。Worker 读取一个任务，原子变为 running；解析成功后一次事务写入内容块并标记 completed。失败写入可读错误，不留下“成功但缺块”的记录。

DOCX 不执行宏或嵌入对象，不使用 extractall；只读取 OOXML。支持基础分数、上下标、根式。矩阵、方程组、分隔符和其他复杂结构提示不完整，禁止猜测为可靠公式。可解码图像转换成内部 PNG。当前是按块结构提取，无真实 Word 页码。

PDF 用 pypdf 提取文字，pypdfium2 渲染页面；最多120页，页面长边控制约2000像素。扫描件无 OCR，保留图并要求补录。跨页题需人工选中多个块。内容块不是可靠题目边界。

Worker 重启获得独占锁后将运行中任务重新排队，从文件读取阶段重做。不是从模型中断 token 恢复。失败任务只能显式重试。重做可能留下未引用的图片，基础版尚无垃圾清理机制。

## 审核与交付不变量

1. 未核对来源不能创建单元。
2. 修改来源会使所有关联草稿递增修订并撤销批准，即使正文尚未重写。
3. 修改正文撤销批准。来源修改和正文修改都必须匹配客户端持有的 revision，否则409。
4. 批注与批准同样绑定 revision，不能把旧页面的批准应用到新内容。
5. 只有当前修订批准且来源仍已确认，才能固定交付。
6. 交付保存完整来源与图片。后续来源、正文和审核变更均不改变已有下载内容。

离线 HTML 使用转义后的修正文字，不继续使用可能过期的结构预览；图形以 data URI 嵌入。复杂公式的正式排版待后续实现。打印由浏览器完成，无服务端专业 PDF 引擎。

## 本地安全边界

默认仅回环监听，校验 Host 和浏览器写请求 Origin，不允许任意来源执行修改。无身份系统：同机进程仍可调用 API。用户文件不上传 Git，不调用模型。下载原件使用内部 ID，不接受用户路径。

正文始终转义显示；DOCX 预览只从自有转换器生成允许标签，不放行原始 HTML、事件或外链。导出 HTML 带限制性 CSP。文件大小、ZIP 展开总量和页面渲染大小有基础限制；解析仍在 Worker 进程内，尚无独立进程的 CPU/内存/超时隔离。生产化前必须补上隔离及更完整的异常回收。

## API

接口与请求字段以运行后的 /docs 为准。主要路径为 /api/documents、/api/jobs、/api/blocks/{id}、/api/drafts、/api/drafts/{id}/comments、/approve、/preview、/releases，以及 /api/releases/{id}/download。

0.2 新增幂等增量迁移：plans、plan_draft_links、schema_migrations，不修改或删除0.1表。plans.payload保存有来源的教材节点、小册子单元、课标摘录与对应、来源修订和人工说明。confirmed_revision绑定当前规划修订；来源变化使其过期并撤销关联草稿批准。已有交付快照不变。尚无通用迁移框架；以后修改既有表仍需独立迁移与恢复测试，不得删除数据库代替升级。

规划 API 位于 /api/plans。识别是标题规则，不是 AI；结构调整、确认及单元提纲创建均校验修订。节点父子关系拒绝循环，来源不可伪造；课标摘录必须来自已核对的课标类别原文。单元与草稿一对一绑定，重复创建返回原稿，防止覆盖人工修改。

规划同时保存来源原文哈希和修订号：仅变更目录条目的核对状态，不撤销结构确认；修改原文或取消课标核对则过期。正文草稿的审核仍按原有保守规则失效，不能由规划确认替代。

连续核对新增 PUT /api/documents/{id}/blocks/review。一次提交明确范围内的来源ID、修订、文本与确认状态；事务内先完整验证，再批量写入。拒绝重复ID、跨资料ID与过期修订，任一错误整批回滚。依赖失效以受影响草稿ID集合处理，每批只递增一次。原有单块接口复用相同逻辑并保持兼容。

公式迁移版本2增加 blocks.original_content 与 formula_candidates。原生 OMML 转显式 LaTeX，正文使用明确公式边界，API派生内容分段及安全 MathML。保存草稿允许待修正表达式，但确认来源与批准正文时校验支持范围和可渲染性。转换不支持时保留提示，不把 token 拼接作为成功。

重新提取按原文档块ordinal关联既有ID，只写候选及基准修订，不触碰当前正文和批准。应用候选仍走原编辑接口与并发检查。新交付保存 format_version=2 和固定渲染HTML，旧交付默认使用旧转义文本格式。MathML通过限制性转换器产生，无脚本、外链或事件属性。
