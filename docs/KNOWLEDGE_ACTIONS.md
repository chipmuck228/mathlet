# 定向完善、完整性检查与知识关系

状态：2026-11-11 已实现。当前工作单位是一个知识候选批次，可包含多个章节；不是全册自动课标认证。所有模型输出是候选。

## 教师操作

1. 打开“知识与关系”，选择已有知识批次。无需重新生成旧知识。
2. 在知识条目上点击“让 AI 补充／修订／拆分”，跳转“AI 定向完善与知识连接”。也可在此直接选择整个批次。
3. 勾选核查意见，或输入一句要求，例如“将增减性、全体实数最值和闭区间最值方法拆开；动区间内容另列拓展”。不需要教师输入完整知识正文。
4. 确定任务类型、每批数量（1—4），确认发送当前知识与要求，开始任务。修订返回一项，拆分至少两项；生成知识后另发一轮独立模型复核。
5. 下拉选择已有完善任务，查看原稿对照、模型初始建议和复核意见。可编辑候选并保存；有未保存修改时禁止采纳或切换任务，暂停结果轮询以保护输入。
6. 一次勾选本任务要采纳的全部结果，填写处理人及依据并明确确认。采纳知识只是写入待审核条目，仍需选择适用范围并执行知识审核。退回不会改变原知识。
7. 拆分必须整组采纳。原条目不删除，保留原文，标为“待审核、不纳入”；新条目独立审核。修订保留知识 ID 和历史，撤销受影响条目的批准；未改动条目的正文、范围和批准不变。

每次采纳会改变原批次修订号，同一任务未采纳的剩余结果和其他旧任务随之过期。若要继续完善，请基于当前知识重建任务。分类意见同样会改变相关条目的修订号和原批次修订号。

## 核查意见分类

| 类别 | 意义与处理 |
| --- | --- |
| 数学正确性 | 判断定义、条件、结论与反例；内容自身未解决的数学问题须修改并清空后才能批准 |
| 适用范围 | 教师决定基础、综合、拓展或不纳入，不必为范围疑问重写数学正文 |
| 内容组织 | 决定保留、拆分或补充关联 |
| 教学建议 | 决定术语解释、例子与训练方式 |
| 系统信息 | ID、来源核验标志等不作为数学错误阻止审核 |
| 待分类 | 旧意见不靠关键词猜测，保留为待分类供教师判断 |

模型会建议类别，教师可调整，必须填写分类依据。`uncertainty` 作为独立意见显示，其分类与该文本内容绑定；文本变化后旧分类不再有效。数学问题不能靠填写“已处理”绕过，需修正并清空；教师判断其实际属于范围、组织或教学问题时可分类并记录理由。非系统意见的纳入项仍需教师处理说明和明确确认。改变分类会撤销受影响条目的旧批准，旧发布文件不变。

## 完整性检查

任务类型选择“检查遗漏与组织”，不必填写额外要求。模型收到单元范围、全部清单和已展开正文，提出可能遗漏、尚未展开、重复、过大条目或缺失连接。数量上限只限制本批建议，不表示知识总量。

建议不能直接当知识纳入。选中建议，在上方选择补充／修订／拆分（后两者需指定原条目），点击“按选中建议生成知识”。模型生成正文后再审阅。与清单中未展开条目同名且同类型的补充，采纳时复用原清单 ID，避免重复建项。

检查依赖模型已有知识和教师范围，未读取或核验官方课标，`official_coverage_verified` 保持 false。没有建议也不代表完整。不会自动循环调用模型；每轮须人工发起，可查看调用记录和预算。

## 关系候选

选择“生成知识关系候选”。关系端点只能使用当前批次已有知识，模型不可编造端点。可跨本批次涵盖的章节；跨批次或跨单元图谱尚未实现。

| 类型 | 方向含义 |
| --- | --- |
| prerequisite | 起点是终点的前置知识 |
| derives | 起点在指定条件下可推出终点 |
| uses | 起点方法使用终点知识 |
| contrast | 从起点对照终点，帮助区分 |
| representation | 起点到终点的表示转化 |

每条必须有理由、条件和使用例子。页面显示知识名称、方向与类型，可编辑端点、类型和文字，保存后由教师明确确认采纳。候选可基于尚未批准的知识提出，但只有两端知识都已审核纳入、且端点修订号未变化时，关系才可进入固定知识版本。建议先完成知识审核，再生成并审阅关系，减少返工。

知识任何修订（含范围、分类或批准修订号改变）都会使绑定旧端点修订号的关系过期，旧关系保留供参考。重新生成关系可重新审阅；同方向同类型的有效关系不可重复采纳。发现已采纳关系不合适，可填写撤回处理人和原因，点击“确认撤回此关系”；保留旧关系与撤回依据，不影响知识正文及旧知识版本。随后可重新生成和审阅关系。当前只提供关系列表，不提供全册图谱编辑器。

## 数据与执行契约

- 继续使用单 Worker、知识任务队列、配置快照、调用次数与输出预留预算、成功步骤缓存、显式失败重试与中断恢复。定向知识任务预留7000＋2200 tokens，完整性或关系任务预留4000；模型实际用量以服务商报告为准。
- `POST /api/knowledge/runs/{id}/actions` 创建独立任务，冻结原批次修订号、知识正文、清单、所选意见、教师要求与建议来源。发起须确认发送范围。原件和认证密钥不作为模型正文发送。
- `POST .../classify` 保存意见分类与依据；不表示内容批准。
- `PUT /api/knowledge/outputs/{id}` 编辑候选，保留 original_body 和历史；旧修订号拒绝覆盖。
- `POST /api/knowledge/runs/{task_id}/apply` 按任务和原批次修订号原子采纳／退回。知识采纳保持待审核；关系采纳记录教师身份与依据。
- `knowledge_outputs`、`knowledge_output_history`、`knowledge_relations` 为新增持久表，迁移版本5可重复执行。不改动原件、原有草稿与已固定版本。
- 原知识、单元或关联规划在执行期间变化，结果不会写入；已生成但过期的结果只供参考，不能采纳。首次生成与复核失败均保留调用证据；重试复用已成功调用，不自动重发付费请求。
- 固定知识版本只包含已审核知识及可用已审关系；完整性建议和未采纳候选不混入。已有版本字节不变。

## 验收边界

自动化使用合成知识和模型替身，验证结构、状态与版本契约，不等于真实 DeepSeek 成功率或数学质量验收。真实内容仍由教师决定范围、检查推理与确认。题目研究、单元出版、动画和全册课标覆盖尚未由此功能完成。
