# 知识稿件编制工作区

当前“知识与关系”使用 `EditorialKnowledgePage`，面向教师编制稿件。旧 `KnowledgePage` 和逐条审核接口保留作兼容与回归，不再是主导航页面。

## 主流程

1. 从已确认内容规划选择领域下的主题，创建／打开知识单元；或直接打开已有知识单元及稿件。
2. 需要新初稿时点击“生成知识清单与初稿”。按钮即授权本次生成，不再额外勾选调用声明。新任务自动从清单展开全部条目；若预算不允许展开，可选择较少条目。打开历史稿件不会触发模型调用。
3. 左侧选择、排序或移出条目；移出可恢复，不删除原始证据。
4. 中央使用“浏览／编辑”切换，直接编辑整条正文、公式、范围及编制说明。保存仅更新工作稿；保存失败保留编辑输入。
5. 右侧可与 AI 讨论当前条目。发送时包括当前未保存正文、清单摘要及该条最近六轮成功讨论；界面记录所用修订和是否含未保存编辑。AI 不覆盖正文，回复可复制，公式源码可展开复制。
6. 需要增加知识时选择“补充知识候选”，输入要求，由 AI 最多提出三项。教师选入后成为待确定范围的工作内容。采纳绑定原稿修订，禁止跨稿件、重复或过期采纳。
7. 左侧集中确认整份清单并“形成终稿”。这是真实的整稿教师确认，不是 AI 批准。正文必需字段、范围和公式结构仍会检查；AI 的范围或数学疑问是提醒，不作为自动否决。
8. 终稿只读。点击“基于终稿继续修订”创建新工作稿，再定稿产生新版本。旧文件不变。关联内容规划或编制范围已变化时，先核对范围，不能悄悄沿用旧范围形成新终稿。

## 版本与历史

“知识单元与稿件”提供统一历史入口：工作稿与固定终稿。历史稿件直接恢复原内容，没有重新生成前置步骤。界面标注 V1、V2 等，固定文件仍采用已有 `knowledge_versions`，供“题目与研究”使用。

保存、排序、移出、选入候选均以修订号校验，撤销受影响的旧确认或生成新的工作修订。终稿修订另建运行记录，不调用模型。新终稿只包含当前纳入的知识条目，不把 AI 生成关系写为教师已审核关系。历史旧版本的已审核关系仍原样保留。

为兼容旧接口，旧接口仍可能在固定文件之后产生新工作修订；固定文件本身不可变。打开终稿时始终读取版本快照，AI 讨论也可显式绑定该快照，避免使用较新的工作正文。

## 五套模型配置

固定提供 OpenAI、Gemini、DeepSeek、Grok、其他兼容服务五个槽位，分别保存地址、实际模型 ID、密钥及高级设置。地址预填，不预设可能过时的模型型号。均通过 Chat Completions 兼容协议；Gemini 采用官方兼容入口。

旧模型配置首次打开时迁移到相应槽位。密钥只写入本地私有配置文件，不出现在 API 响应、调用上下文、版本或 Git 中；留空仅保留本槽位密钥，不能继承别家密钥。配置校验错误也不回显请求中的密钥。存在排队／运行中的生成任务时暂不切换活动服务，以免重试误用另一模型。每次 AI 讨论可独立选用当前活动模型，历史消息保留实际调用模型。

官方兼容协议参考：
- https://ai.google.dev/gemini-api/docs/openai
- https://docs.x.ai/developers/quickstart

## 知识关系

独立标签页根据当前已保存清单生成，最多十二条，校验端点存在、无自环、类型及成立条件等字段。显示“AI 生成，未经教师核验”，不提供逐条审核按钮，也不自动进入终稿。清单变化时提示结果可能过期。教师基于终稿讨论或生成关系时使用该终稿快照，和工作稿讨论分开。

## 调用记录与边界

每次讨论、补充或关系生成都先持久化请求及模型快照，再执行一次真实调用，最多预留 4000 输出 tokens。成功、失败、用量、原始回复和上下文均保留。请求编号防止重复提交计费，不自动重试。失败时人工决定是否另发请求；浏览器断连或 API 进程中断可留下“尚无完成结果”，不将其标为成功。知识初稿继续使用单 Worker 的原有断点与预算机制。

本版没有真实服务密钥的跨供应商在线验收，也不声称已核验官方课标全文或数学证明。AI 输出是候选；教师对终稿内容负责。

## 数据迁移与验证

迁移 7 新增稿件排序／移出元数据、讨论记录和候选采纳记录，幂等建表，不改写已有知识或固定版本。API 以 `/api/editor` 提供，旧 `/api/knowledge` 接口与研究流程继续兼容。

验证包括五槽密钥隔离、历史免调用打开、未保存正文进入讨论、对话不改正文、整稿确认、旧版本不变、继续修订、来源变化拒绝、条目移出恢复排序、候选过期／跨稿／重复拒绝、关系端点检查与未经审核标记。测试使用合成资料和模拟模型响应，未执行付费模型调用。
