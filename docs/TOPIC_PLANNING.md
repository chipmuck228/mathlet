# 主题规划实施计划

目标：用“课标学习要求＋教材目录线索”形成可核对的主题规格，让知识正文和训练围绕同一组目标编写。课标归纳是用户上传的来源资料，不等于系统已验证官方原文；AI建议与逐字引文分开。

## 阶段 1：联合资料与主题规格（已实现）

入口：课标/考纲整理 → 领域与主题规划。

1. 展开“用 AI 构建领域与二级主题”，主资料建议选课标归纳，联合参考选教材目录。界面支持两份联合资料；后端最多五份。预览全部正文并绑定每个来源块修订；新任务生成新规划，不覆盖已有规划。
2. AI区分课标要求和目录线索，形成领域、二级主题及学习要求对应。不能把目录章节名称当作官方掌握要求，不声称全册完整覆盖。
3. 在“2 主题目标”选一个主题，查看“主题规格”。可直接编辑，也可展开AI补充区域，点击生成。读取当前规划绑定的资料、主题、已有目标与已关联来源要求；采用建议前只保存为任务结果。
4. 建议包括可逐条核对的学习目标（稳定目标ID与来源要求ID）、必含内容、基础内容边界、综合／拓展候选、前置知识、相关主题与连接理由、常见困难、呈现建议、逐字依据及资料缺口。不是每个主题都必须包含所有知识类型。
5. 点击“采用建议到编辑区”后可以继续编辑。保存规划修改 → 在“核对与确认”整体确认。没有增加逐条审核或每个字段的批准。缺少规格不阻断已有规划和知识流程；已有规划、知识终稿和交付文件不被重写。
6. 从已确认规划创建知识单元时，将主题规格及人工确认来源一起带入origin快照。规划修改使旧来源关联失效；不自动更新或重新批准旧知识稿。旧知识终稿、旧小册子交付仍保持原文件。

主题规格与历史目标说明并存：原goals保留作为原规划说明；规格里的objectives是结构化学习目标。此阶段不自动删除或替换旧说明，不生成“学习目标覆盖率”。

### 技术边界

- 复用knowledge_runs/knowledge_calls/knowledge_outputs与单Worker；无需DB迁移。不增加同步请求内的模型调用。
- POST /api/topic-specs/runs、GET /api/topic-specs/runs?plan_id=…&unit_id=…、POST /api/topic-specs/runs/{id}/retry。
- 单次规格任务预留5000输出tokens，输入不超过1000块/90000字符；过大时明确拒绝，不截断正文。
- 任务绑定规划ID、主题ID、规划修订及来源有效性；生成前、完成前和采用时检查版本。生成建议不会改变规划确认状态；采用后保存撤销当前规划确认。
- 来源引文必须来自绑定资料并逐字连续匹配；目标只能引用该主题已关联的来源要求。没有直接要求依据的目标明确显示为教研建议。
- 依据按钮按实际来源文件打开，不再假定所有内容都在主文件。新增来源块或修改联合资料，也会使当前规划失效。
- 学习目标、边界和连接均为规划建议，不是数学正确性证明，也不是已完成官方覆盖核验。测试使用合成资料与模型桩，未执行用户本地真实模型调用。

## 阶段 2：按规格生成与学习目标覆盖表（已实现）

- 新知识任务把已确认主题规格显式带入输入快照。清单可多对多关联稳定学习目标ID及必含内容序号，检查引用有效性；正文围绕对应目标补齐表述、条件、公式、正反例与掌握表现。缺少绑定不冒充完整，后续独立检查仍按实际正文判断。
- 有结构化规格的任务，在正文与数学复核后自动执行一次目标覆盖检查，记录到独立的objective_coverage输出。覆盖检查失败、模型响应格式问题或预算不足只记录具体原因，保留知识工作稿，不使正文任务失败，不阻断教师整稿定稿。来源失效仍拒绝。
- 基础知识编制同页增加“学习目标与必含内容覆盖”：逐项目标/必含内容→纳入知识条目→准确表述/条件/正例/反例等具体字段→缺口与处理建议。使用“已有内容、部分涉及、待补充”，不计算学生掌握率或官方覆盖率。旧结果显式标待重查，避免保留绿色当前状态。
- 可直接编辑覆盖判断、知识关联、缺口、建议与教师说明，不依赖模型或API Key。引用必须指向当前纳入条目的真实非空字段；每个目标列一行，保留多对多关系。修改覆盖判断只更新工作稿修订，不另设批准按钮。
- 缺口可“带入右侧AI补充”；组织、过度合并或边界建议可带入右侧讨论并定位知识条目。仍由教师点击发送，AI输出为可选择补充候选或可复制修订建议；不自动覆盖正文、不自动纳入或批准。采用补充/修改正文后，覆盖结果因内容指纹变化而失效，需要重查。
- 覆盖快照及清单目标关联随知识终稿固定，历史文件不重写；基于终稿继续修订保留清单的目标关联，新稿需重新检查覆盖。旧稿未带入主题规格时不强行生成虚构目标；可先从已确认主题规格创建知识单元。

### 运行与版本保护

- 复用单Worker、knowledge_runs、knowledge_calls和knowledge_outputs；不新增数据库迁移。新知识清单提示词为knowledge-v2，目标覆盖提示词为objective-coverage-v1。
- 有规格的清单预留4000输出tokens，覆盖检查预留6000；无规格的原流程不额外调用覆盖模型。默认预算不足时正文仍保留，并可点击AI重新检查创建独立任务。
- GET /api/knowledge-coverage/runs/{id}；POST /api/knowledge-coverage/runs/{id}/check；PUT /api/knowledge-coverage/runs/{id}。
- 独立检查绑定父稿修订、正文/纳入条目/规格的指纹和来源有效性；相同范围的执行中请求复用任务。教师期间修改或定稿后，旧AI结果拒绝写入。
- 手动保存同时核对父稿修订、内容指纹及覆盖结果记录ID，拒绝覆盖另一轮新结果，客户端保留未保存判断。原AI输出及历次记录保留；覆盖判断与数学正确性分开。
- 已审定JSON额外保存topic_coverage与topic_catalog_bindings；这些是工作台/后续编排依据，不在学生小册子中直接展示内部ID或审核报告。
- 测试使用合成资料和模型桩，未使用用户本地密钥进行真实模型调用。当前覆盖检查是AI内容检查及人工判断，不是通用数学证明。

## 阶段 3：贯通真题、思路训练与复习单元（已实现）

- 知识终稿向复习单元携带主题规格、知识覆盖判断和清单目标绑定。它们作为来源快照保留，不自动升级为“数学已证明”或“学生已掌握”。没有结构化目标的旧知识终稿不强造目标，既有知识/研究/训练流程仍可使用。
- AI映射仍逐题引用真实研究步骤；代表题选择在既有核心考察优先级内兼顾目标差异。思路卡与训练增加可选target_ids；生成时明确按基础边界安排，不自动将拓展候选当基础要求。
- 完整单元草案增加自动“目标与训练对应”检查，按每6个目标一批，保留目标→知识→研究证据→跨题卡→基础/思路/独立解题/迁移任务的多对多关系。每个关联须有实际知识与研究依据，不以关键词凑覆盖。
- 区分缺基础知识、缺合适研究题、缺思路/独立/迁移训练，以及组织和边界疑问。基础阅读可以支持basic；按目标性质选择expected_phases，不强迫每个目标都有跨题卡或迁移题。判断为“已安排路径／部分安排／待补基础”，不是掌握率或考试分数承诺。
- “复习单元编制”左侧新增“目标与训练对应”栏目。中央逐目标展开/折叠，可阅读、直接编辑引用与安排判断、学生问句和教师说明；知识与研究终稿本身保持只读。引用可定位基础条目、题目研究证据、思路卡、训练；支持带入右侧AI讨论，回复仅建议，不自动采用。
- 对应表随同一次“保存单元修改”和整体审定完成，不增加逐项批准。AI检查失败、证据文本过大、缺题或目标缺口不阻断整体定稿。知识、研究来源失效及过期版本仍拒绝。
- 修改映射、卡片、训练或知识连接后旧表标为待重新检查。仅修改对应表不使学生表达失效，也不要求重新研究题目；可点击“AI检查／更新目标对应”，只生成新表并保存新修订。执行中界面暂时以阅读为主，防止同时修改；服务端仍会拒绝覆盖期间发生的教师修改或定稿。
- 学生读物新增“想练哪一件事？”折叠入口，只显示可读问句及真实基础/思路/训练链接；仅使用当前对应表，隐藏缺口、角色、内部ID与审核报告。问句含教研说明或内部标记时不输出，仍保留在教师稿中供修订。
- 对应表、来源与教师说明随单元JSON/离线HTML终稿固定；旧交付文件不改变。继续修订形成新版本，学习路线是否完整仍由教师根据本次单元定位决定。

### 阶段3运行边界

- 复用单Worker和现有任务、版本、历史表，无新增DB迁移。单元正文增加goal_coverage；每个思路卡/训练可选target_ids。提示词unit-goals-v1。
- 每批最多6个目标，预留5000输出tokens；启动完整编制时将目标批次一并纳入调用预算。单批完整证据/知识/训练输入超过180000字符时明确保留未完成原因，不截断后声称检查完成。
- POST /api/review-units/runs/{id}/goal-coverage 创建独立检查任务；绑定父稿修订及有效知识/研究来源，相同修订执行中请求复用。教师中途修改或定稿后，旧结果不写入，历史文件仍保留。
- 人工编辑校验目标全集、真实知识/题目、有效卡片/训练索引、共同知识与来源证据。旧表失效时允许保存/定稿正文，但不将旧表作为当前学生路线；显式修改对应表后，才基于当前内容重新绑定。
- 研究范围很大或模型返回不完整时，可重试独立检查或直接人工编排。当前未提供自动向原题库补采真题、自动证明数学结论、自动发布或学生答题能力测量。
- 测试使用合成资料与模型桩，未调用用户本地模型或修改用户试卷。真题与图形的完整性、概念/条件与训练解答仍需教师整体审阅。
