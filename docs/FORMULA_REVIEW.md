# 公式核对与编辑

此更新修正编辑正文直接拼接数学字符的问题。新上传 DOCX 的原生 Office Math 会转换为明确的公式表达式，不再把上标或分子分母当作相邻文字。

## 本地操作

停止旧服务，执行 `git pull --ff-only`、`python3 scripts/setup.py`、`python3 scripts/dev.py`。依赖包含 MathLive 和 latex2mathml；首次安装需要网络，运行时编辑器代码与字体均从本机提供，不要求模型密钥。

新上传资料：进入“原题核对”，左侧的数学公式以公式形式显示。点击公式打开可视化编辑框，可用键盘、数学键盘或平方、下标、分式、根式等模板修改。下方同时提供 LaTeX 输入，适合熟悉语法的编辑者。

普通文字中需要新增或替换公式时，先在文字区选择待替换字符，如 x2 或 1x，再点击“插入公式并替换选中文字”。没有选择时，在记录的光标位置或当前来源块末尾插入。不会根据 x2 自动猜成平方，需编辑者明确输入。应用后只是本地修改，仍需保存或选择范围后保存并确认。

例如平方为 `x^2`，下标为 `x_1`，分式为 `\frac{1}{x}`，根式为 `\sqrt{x+1}`。普通文字与公式分别编辑，公式表达式被明确包在 `\(` 与 `\)` 中保存。界面显示公式而不是要求读者阅读标记。

## 已有资料

已有正文、人工修订和批准不会自动改变。对于此前已压平的 DOCX，点击“重新提取公式候选”。系统从保留的原始文件读取，生成与原来源ID、修订对应的候选，不覆盖现有内容。

展开对应块下的候选，将上方当前正文与候选、右侧原件提取预览对照。采用候选会替换本块的全部文字，所以必须保留需要的人工修订；采用后仍不会自动保存或确认。已经修改过来源的旧候选会禁止采用，需要重新提取。PDF 与图片公式暂不支持自动公式识别，可对照图像手工插入公式。

## 提取范围

支持常见原生公式的分式、上下标、二次及高次根式、单参数括号分隔与部分函数和多行结构。所有转换仍需要人工对照。纯 Word 上下标字体运行无法自动判断其底数范围，会保留明确提示而不是猜测；复杂矩阵、特殊重音、旧式公式对象及图片公式不保证转换。

不支持的结构显示“未转换公式，请对照原件并替换”，并保留原件和必要的原始公式信息。包含未处理占位或错误公式的来源不能确认；可以先保存为待核对草稿。数学语法可解析并不表示数学含义或解题结论正确。

## 数据与交付

增量迁移增加 blocks.original_content 及 formula_candidates，不清空数据库。original_content保存初次提取内容，text保存带明确公式边界的当前正文，API另返回文字与公式分段和安全 MathML。保存公式更改遵循原有修订冲突检查、规划过期与草稿批准失效规则。

单元预览、新交付的来源及正文从保存后的表达式渲染 MathML，离线 HTML 无需联网公式脚本；可用现代浏览器打开和打印。新交付固定渲染后的 HTML；旧快照按旧文本格式兼容，不因公式升级改写已有交付。

Agent 尚未接入。未来应接收带边界的表达式或结构化分段，不能读取丢失结构的纯字符。此版本没有代数证明或语义正确性自动验证。

## 已知验证限制

MathLive 编辑器采用延迟加载，并将字体复制到本地 public/mathlive/fonts；声音和计算引擎关闭。自动化覆盖提取、保存、重开、输出与组件替换行为；真实数学键盘、移动端及打印版式仍需本机浏览器验收。DOCX 右侧依然不是 Word 原页渲染。
