# 复习单元编制

## 目的与入口

工作台“复习单元编制”从一个有效知识终稿出发，默认扫描全部有效研究终稿。教师不需要先挑题，也不需要分别批准映射、思路卡或训练。点击“生成完整复习单元草案”发起真实模型任务，完成后在同一页面阅读、编辑并整体确认。

教师已定稿的知识、原题与研究解析作为版本依据直接引用。新生成的映射、思路卡和训练是待审核草案，不能冒充已经审核的内容。关系开放、同题允许多解，不押题。

## 自动工作流

1. **确定来源**：只使用当前有效研究终稿，按研究日期取有效版本；同一原题的多份试卷或多个研究版本自动合并。可以展开题库范围改为指定题目。发起后固定研究ID与摘要哈希，新增题库记录不会静默改变正在进行的任务。
2. **分批映射**：逐题对照知识终稿，保留核心考察、辅助使用、可选解法、无关联、依据待判断五种结果。每条关联绑定研究版本、解法编号、从0起的步骤索引及该步骤的逐字证据，同时解释知识的作用和条件。目录外知识记为缺口，不自动改写知识终稿。
3. **选择代表题**：优先核心考察，兼顾知识覆盖与题型差异，默认最多4题，可设2—8题。所有扫描结果仍保留在映射栏目，不只保留入选题。教师可修改代表题选择，同时需检查思路卡和训练的引用。
4. **跨题归纳**：至少有两道不同原题的证据才能形成跨题思路卡。说明线索、结构、操作、边界、不同路径和易错点；证据不足可以没有卡片，不强行概括。
5. **训练编排**：依次覆盖基础唤起、思路训练和独立解题，可增加迁移。每项提供来源、知识、任务、逐层提示、答案、推理和检查点。优先围绕原题安排，自编题明确标注，不能冒充真题。原题和审定解析保持原文。
6. **AI复核**：复核新增内容并逐项说明疑问与处理建议，不代替教师批准。不匹配、缺口和没有应用证据的知识会显示在核查栏，不能据此删掉基础知识。

无匹配题时，保留基础回顾并明确“尚未形成训练闭环”，不编造代表题、思路卡或训练。教师可以审定为基础读物，或补充研究后重新编制；系统不声称此时已有完整训练单元。

## 核对界面

- 左：单元目录、核查意见数量、选填审核说明、整体确认、终稿下载与修订入口。
- 中：单元导读、基础知识、映射、思路卡、训练、已审定解析和回顾。浏览／编辑在中央切换，文本可直接编辑并在选区插入公式；公式即时可读预览。基础知识与既有解析只读，如需修改回到相应来源形成新版本。
- 右：当前栏目的具体疑问与处理方式、全部意见、原题步骤证据及AI讨论。讨论携带当前栏目（包含未保存修改）、知识及代表题，回复只供复制或参考，不会自动覆盖正文、修改审核状态或形成终稿。

保存单元修改只保存工作稿。正文未保存时不能定稿；选填审核说明与定稿一起提交，不需另行保存。页面切换和关闭会保护未保存内容。AI意见、知识缺口或归纳疑问不会自动否决教师整体确认。

## 版本与运行

新增数据表：`review_units`、`review_unit_history`、`review_unit_versions`、`review_unit_requests`、`review_unit_discussions`，幂等初始化记录迁移15。内部任务复用现有 `knowledge_runs`、`knowledge_calls` 与单Worker，不需要新服务或新的模型密钥。

主要接口前缀 `/api/review-units`：

- `GET /catalog`、`GET /runs`：有效知识与研究目录、单元历史。
- `POST /runs`：创建来源固定的自动编制任务，request_key实现重复请求幂等。
- `GET /runs/{id}`、`PUT /runs/{id}`：读取／保存整份单元，保存须同时提交稿件与任务修订号。
- `POST /runs/{id}/retry`：重试失败或中断任务，复用成功调用检查点，不覆盖教师稿件。未知外部调用用量保留为未知，重试由教师主动触发。
- `POST /runs/{id}/finalize`：教师一次性确认整个单元；保存教师说明、AI意见、知识及研究来源、模型配置快照（不含密钥）。
- `GET /runs/{id}/studies/{analysis_id}`：按需查看本次范围内的研究证据。
- `GET/POST /runs/{id}/discussions`：持久化AI讨论；讨论独立排队，包含基于哪个正文修订和是否使用未保存修改的记录。
- `GET /runs/{id}/preview`：未审定阅读草案。
- `GET /versions/{id}/reader`、`download`、`json`：固定阅读文件、离线HTML与JSON。
- `POST /versions/{id}/revise`：基于终稿创建新的工作稿；旧终稿与文件保持不变。

所有当前稿件保存、生成写入与定稿检查知识和研究来源是否仍有效。来源变化后需用当前材料重新编制；已发布快照仍可下载。不存在的引用、伪造的逐字证据、失效来源、版本冲突等技术约束仍会报出具体问题，这些不同于AI数学判断。

整个题库通过分批扫描处理，不静默截断。知识正文限制120000字符、单题研究限制120000字符；超限在发起前明确拒绝。每批最多5题、目标65000字符，过大的单题独立成批。创建任务按完整流程预留调用预算（含一次重试余量），调用记录折叠显示。预算耗尽会停止，不无限自动重试或计费。

## 阅读交付与当前边界

阅读版为独立HTML，公式使用MathML，原题PNG内嵌，文字经过转义，答案与提示可逐层展开。可离线保存；浏览器打印为PDF前展开所需答案与解析。此版没有后台直接生成PDF、自动生成动画或公开网站发布功能。

自动化测试使用合成的10项知识、两道已审定研究及模型替身，验证闭环、引用约束、重试、教师优先、讨论不覆盖正文、来源变化及旧交付不变。真实题库与实际模型的生成质量需由本地教师试用核查；自动复核不等于数学正确性证明。

### 引文自动绑定与历史失败恢复

模型不承担逐字重抄公式和解题步骤的可靠性。生成时，以研究终稿ID、解法编号和步骤索引从本机直接读取原文：定位有效而AI改写了引文时，替换为该步骤原文，并保留AI原引文和具体核对说明。此操作只修复引用，不宣称知识关联在数学上成立。步骤编号不符时，只有逐字引文在该题中唯一匹配才自动调整；否则移除不可定位的关联，并将无可用关联的题目保留为“依据待判断”，其他题继续生成。不以无依据的匹配填满单元。

思路卡同样绑定真实步骤；可定位证据不足两道不同题的卡不纳入，并明确说明原因。教师编辑保存仍校验引用是否存在和引文是否对应，来源变化与版本冲突仍拒绝。

对于此前因逐字引文或步骤定位校验失败、且已保存完整模型响应的 `unit:mapping:*`／`unit:cards` 调用，点击重试会先按当前规则重新校验旧响应，成功标记为 `revalidated`，不再次支付这一步的模型调用。后续尚未生成的环节仍会正常调用；无法解析的响应、失效来源、模型服务错误等不冒充恢复成功。

### 基础知识与单元连接的职责分离

基础知识在“基础知识编制”中整体审定，无需设置教学分层或预先生成关系。复习单元的训练编排调用可同时返回可选knowledge_connections，说明本节知识之间的理由、成立条件和例子，教师在“知识连接”栏目随整份单元审核。连接可以为空，不增加独立生成／批准步骤。旧的关系作为历史参考，不自动视为新正文关系已审核。详见 [FOUNDATION_AUTHORING.md](FOUNDATION_AUTHORING.md)。
